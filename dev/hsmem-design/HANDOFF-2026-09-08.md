# Передача: fpl-hsmem — что выяснено, что решено, что делать

Дата: 2026-09-08. Источник: сессия в `gerts-hub`, где Hindsight разбирали от «а что там вообще есть»
до целевой архитектуры. Этот файл самодостаточен — принимающей сессии не нужен исходный диалог.

## 1. Решения владельца (границы, внутри которых работаем)

Эти решения приняты человеком и не пересматриваются агентом:

1. **Свой релей остаётся.** Не выкидывать MCP-часть плагина в пользу апстрима. Писать свой, хорошо
   описать, расширить плагин и написать инструкцию по использованию.
2. **Нужен полный харнес:** MCP с авторизацией, плагин, скиллы, хуки, сабагенты — то есть всё, что
   обычно требуется, — построенное по best practices, а не «как получилось».
3. **Кросс-рантайм обязателен:** должно работать в Claude Code, Codex, OpenCode и далее. Это
   требование заказчика, а не пожелание.
4. **Существующий корпус в 7011 записей оставить как есть.** Маскирование секретов, если включать,
   действует только вперёд; чистку накопленного не делаем.
5. Ночной автоматический процесс обработки данных в хранилище — рассматривается, см. §7.

## 2. Что за система (фактура, проверенная измерением)

- Сервер: `https://hindsight.tools.orch.so`, версия `0.9.1`. Это Hindsight от vectorize-io
  (открытый проект, документация публичная).
- Авторизация: `Bearer ${HINDSIGHT_API_KEY}`. Ключ настроен глобально в `~/.claude/settings.json`.
- Апстримный MCP-эндпоинт: `/mcp/gerts_hub/` — **29 инструментов**.
- REST, к которому ходит наш релей: `/v1/default/banks/{bankId}` — авторитет по формам запросов и
  ответов: `GET /openapi.json` с тем же заголовком.
- Наш релей выставляет **13 инструментов**. Обе версии плагина (2.1.0 и 2.2.0) дают одинаковый
  набор — обновление версии новых возможностей не даёт.
- Наш MCP — тонкая обёртка: каждый инструмент это один вызов `client.*`, а `client.ts` — обычный
  REST-клиент. Логики поверх REST нет. Ценность плагина — в хуках, которых у апстрима нет и быть
  не может (это механизм Claude Code).

**Ролевой модели и «vaults» в Hindsight нет.** Есть роли организации (Owner / Admin / Member),
ключи с ограничением по банкам и сроку жизни, и дочерние ключи через `/v1/api-keys/scoped` с
возможностью `create_scoped_keys`. Граница ресурса — банк. Более гранулярный доступ (команда,
агент, отдельное воспоминание) — открытый запрос функции, не реализован.

**Memory Defense** — маскирование секретов до записи, доступно на всех тарифах. На нашем банке
**выключено** (`GET /config` → `memory_defense: null`) при `store_document_text: true`, то есть
транскрипты хранятся полностью и без маскирования.

## 3. Восемь дефектов в отгруженном коде

Подробности с файлами, строками, воспроизведением и фиксами: `SECURITY-FINDINGS.md` рядом с этим
файлом. Кратко, в порядке починки:

| # | Дефект | Тяжесть |
|---|---|---|
| F1 | `encodeURIComponent('..')` возвращает `'..'`, URL нормализуется в базу банка → `mental_model_delete('..')` целится в `delete_bank` | критично, латентно |
| F2 | `document_ingest` наследует `update_mode: replace`, а id документа = слаг заголовка; UUID слагифицируется в себя → уничтожение документа сессии | критично, активно |
| F3 | `document_ingest_file` читает любой абсолютный путь и грузит файл в банк без маскирования | критично |
| F4 | Снятие маркеров памяти только по парам → воспоминание закрывает свой конверт, остаток читается как инструкция | высоко |
| F5 | Два резолвера имени банка → память проекта расколота на два банка | высоко, уже случилось |
| F6 | `memory_reflect` читает `result.response`, API отдаёт `text`; таймаут 30 с против 49–70 с реальных → не работал никогда | высоко |
| F7 | `memory_status` печатает несуществующий тип фактов, прячет существующий, при сбое чтения показывает нули | средне |
| F8 | `retain_mission` выставлен свободным текстовым аргументом → переписывает правила извлечения всей будущей памяти | высоко |

**F1 сегодня не выстреливает по случайности деплоя:** редирект с базы банка понижает схему на
`http`, `fetch` роняет заголовок авторизации. Это не защита. Если редирект поправят на `https`,
проход откроется.

**F5, измеренное следствие:** два живых банка. `gerts_hub` — 7011 записей, 26 документов, свежая
запись 2026-09-08. `gerts-hub` — 4684 записи, 2 документа, последняя 2026-09-03. Всё, что было до
3 сентября, писалось в банк с дефисом и сейчас невидимо для recall. При этом в осиротевшем банке
пропорционально **больше** ценного слоя: 1674 `world` и 1254 `experience` против 1134 и 549 в
активном.

## 4. Конфигурационная опасность (не код)

`hindsight-full` — HTTP MCP-сервер на `/mcp/gerts_hub/` с полной апстримной поверхностью, включая
`delete_bank`, `clear_memories`, `update_bank`.

Он сводит на нет главный принцип защиты релея: опасные операции у нас не существуют — нет схемы,
нет обработчика, звать нечего. Сервер рядом, у которого они есть, делает этот отказ декоративным.

- Из `gerts-hub/.mcp.json` — **убран** 2026-09-08.
- В `gerts-hub/.codex/config.toml` — **всё ещё есть**, требует удаления.

Список запретов не эквивалентен удалению: его надо генерировать из живого `tools/list`,
перепроверять на каждом релизе апстрима, и он открывается при переименовании инструмента.

## 5. Целевая архитектура

Полный документ: `ARCHITECTURE.md` (86 КБ). Спецификация расширения:
`docs-expansion-spec-v2.md`. Суть в трёх абзацах:

**Главная асимметрия.** Инструменты могут быть мощными, потому что их вызывает человек. Фоновые
скрипты должны уметь почти ничего, потому что за ними никто не смотрит. Текст, приходящий из
памяти, попадает в привилегированную позицию — выглядит как сказанное пользователем, — а взялся из
транскрипта, который никто не вычитывал. Отсюда граница доверия как правило первого класса.

**Состав.** Семь компонентов. Инструментов — 24, каждый с явным уровнем риска. Записи в конфигурацию
банка нет вовсе. Четыре операции отказаны навсегда, без схемы и обработчика: удаление банка,
очистка памяти банка, очистка наблюдений, сброс конфигурации. **Агентов нет** — каждая операция
здесь это один-два запроса с детерминированным ответом, расследовать нечего; к тому же агент,
поставляемый плагином, не может нести свои MCP-серверы и режим разрешений, то есть единственный
случай, где он добавил бы безопасности, платформой запрещён. **Слэш-команд нет** — скилл и команда
с одним именем конфликтуют, команда проигрывает по документированному правилу и потом тихо
расходится.

**Кросс-рантайм.** MCP работает везде — это единственный слой с гарантией в трёх рантаймах из
четырёх. Хуки существуют только в Claude Code; у Codex механизма хуков нет, у OMP и OpenCode —
другие события. Скиллы читаются по разным путям. У Codex, вопреки более раннему выводу в этой же
работе, **есть** механизм агентов (`~/.codex/agents/*.toml`) — на решение «агентов не поставляем»
это не влияет, но основание другое.

## 6. Что делать, в порядке

**Фаза 0 — правки отгруженного кода, отдельным выпуском, без единого нового инструмента.**
F1 (безопасные пути + запрет редиректов), F2 (явный `update_mode` + проверка перед перезаписью),
F3 (`assertIngestPath`), F4 (независимое снятие маркеров + экранирование), F6 (`.text` + таймаут),
F7 (честный статус), F8 (убрать `retain_mission`). Плюс удалить `hindsight-full` из конфига Codex.
Плюс починить шаблоны: они ссылаются на `dist/*.js`, а сборка выпускает `.mjs`.

**Фаза 1 — одна личность, одна версия, первые тесты.** Единый резолвер банка с указанием источника
(лечит F5), единый источник версии (`plugin.json` говорит 2.2.0, `package.json` — 2.0.0), тесты на
безопасность путей и разрешение конфигурации.

Дальше — фоновый слой, поверхность инструментов, документация и скиллы. Порядок в `ARCHITECTURE.md`
§7.

**Две ловушки, которые легко пропустить при починке F1:**
1. `assertPathId` обязан требовать, чтобы первый символ был буквой, цифрой или подчёркиванием.
   Упрощение до класса «буквы, цифры, точка, тире, тильда» **пропускает** `..` — получится
   задокументированная и покрытая тестом дыра.
2. Идентификатор банка нельзя валидировать той же строгой проверкой: он берётся из имени каталога,
   где бывают пробелы, точки и не-латиница. Нужен второй, мягкий валидатор.

## 7. Открытые решения — за человеком, не за агентом

1. **Маскирование секретов** на банке: включать или сознательно отказаться. Действует только вперёд.
2. **Осиротевший банк `gerts-hub`** (4684 записи): перенести, объединить или оставить недоступным.
   Флаги экспорта и импорта документов на сервере включены, но переносятся ли отдельные факты, а не
   документы, надо проверять.
3. **Ротация ключей.** В `.codex/config.toml` токены лежали литералами (в git не попали, файл
   добавлен в `.gitignore`). Но `HINDSIGHT_API_KEY` побывал в контексте сессии, а хуки сохраняют
   транскрипт в банк, где маскирование выключено — то есть ключ, вероятно, уже в памяти как
   обычный текст. Корпус решено не чистить, значит вопрос только в ротации.
4. **Ночной процесс.** Полезен, но **только читающий**: сверять, не завёлся ли ещё один банк,
   ловить неудавшиеся операции (в активном банке их десять), смотреть устаревшие живые страницы,
   проверять состояние маскирования, искать в свежих записях похожее на секреты, считать рост
   корпуса. Ничего не исправлять самостоятельно — отчёт человеку утром. Причина та же, что в §5:
   автоматика без свидетелей не должна иметь права стирать. Браться после фазы 0.

## 9. Как перепроверять утверждения

Всё, что здесь написано, проверяемо за минуту. Полезные команды (только чтение):

```bash
# состояние банка и маскирование
curl -s "$HINDSIGHT_URL/v1/default/banks/gerts_hub/config" -H "Authorization: Bearer $HINDSIGHT_API_KEY"

# сравнить два банка
for b in gerts_hub gerts-hub; do curl -s "$HINDSIGHT_URL/v1/default/banks/$b/stats" -H "Authorization: Bearer $HINDSIGHT_API_KEY"; done

# авторитет по формам API
curl -s "$HINDSIGHT_URL/openapi.json" -H "Authorization: Bearer $HINDSIGHT_API_KEY"

# нормализация пути, из-за которой существует F1
node -e "console.log(encodeURIComponent('..'), new URL('https://h/v1/default/banks/b/mental-models/..').pathname)"
```

Мутирующие вызовы против живого банка в этой работе не делались ни разу и делать их не нужно:
всё установлено чтением и OpenAPI.
