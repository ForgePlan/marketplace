# cross-runtime — wire the project for every installed AI runtime

The assets are portable Markdown. Only the discovery paths differ:

| Runtime | Reads skills from | Reads commands from |
|---|---|---|
| Claude Code | `.claude/skills` | `.claude/commands` |
| Codex | `.agents/skills` **only** | — no command directory at all |
| OpenCode | `.opencode/skills`, `.agents/skills`, `.claude/skills` | `.opencode/commands` |
| OMP | `.agents/skills` | — |
| Any agents.md client | `.agents/skills` | — |

**The failure mode is silence.** A runtime that cannot find a skill does not report a wrong
path — it behaves as though the skill does not exist. That has been mistaken for "this
plugin is broken" more than once.

## Run it

```bash
node ${CLAUDE_PLUGIN_ROOT}/scripts/cross-runtime.mjs            # report
node ${CLAUDE_PLUGIN_ROOT}/scripts/cross-runtime.mjs --fix      # create the missing links
node ${CLAUDE_PLUGIN_ROOT}/scripts/cross-runtime.mjs --all      # include undetected runtimes
node ${CLAUDE_PLUGIN_ROOT}/scripts/cross-runtime.mjs --json     # machine-readable
node ${CLAUDE_PLUGIN_ROOT}/scripts/cross-runtime.mjs --strict   # exit 1 on any gap (CI)
```

Run it from the **root of the project being wired**, not from the marketplace.

Zero dependencies, Node builtins only.

## What it will and will not do

**Creates**: relative symlinks inside the project, so they survive a clone on another
machine and never leak a home path.

**Never deletes anything.** Two cases are reported and deliberately left alone:

- **BLOCKED** — a real directory sits where a symlink belongs. It may hold edits that were
  never in the source; deleting it would lose them. Resolve by hand.
- **MCP wiring** — that config can be user-scoped or shared with other projects. The tool
  prints the command (`forgeplan mcp install --client <name>`) rather than writing someone
  else's configuration.

## How to read the output

| State | Meaning |
|---|---|
| `ok` | linked and resolving |
| `fixed` | created on this run |
| `MISSING` | nothing there — `--fix` creates it |
| `BROKEN` | symlink resolves to nothing. Worse than missing: it reads as present to a human and as absent to the loader |
| `BLOCKED` | real file or directory in the way — needs a human |
| `note` | a runtime quirk with no link to create (e.g. Codex has no command directory) |

The gap count is **distinct paths**, not entries: `.agents/skills` serves Codex, OMP and
agents.md clients alike, so one link closes three rows.

## When it says everything is wired but a skill still is not found

Then the problem is not discovery. Check, in order:

1. **Tool-name spelling.** Claude Code writes `mcp__server__tool` with two underscores;
   OMP collapses it to one. An agent searching for the wrong spelling reports a live server
   as missing. Check the host's own `/mcp` listing.
2. **Whether the entry point is a command.** Codex has no command directory. A plugin whose
   entry point is a slash command needs a pointer skill to be reachable there.
3. **Whether an agent's denylist was carrying the invariant.** `disallowedTools` is a Claude
   Code key and does not exist elsewhere — the restriction silently lapses rather than
   erroring.

All three are documented in [`docs/CROSS-CLI.md`](../../../../docs/CROSS-CLI.md) § portability traps.

## For the marketplace itself

This skill wires a *consuming* project. The marketplace's own producer-side aliases
(`plugins/<name>/.agents/skills/`) are a different thing, generated by
`scripts/gen-interop-skills.js` and asserted by the `interop-skills-check` CI gate.
