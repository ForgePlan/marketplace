# forgeplan-map-pack

> Сканирует любой forgeplan-проект через оркестрованный конвейер из 8 агентов и выдаёт один провалидированный `.forgeplan/map/map.json` — данные, по которым composed-map-вид в forgeplan-web рисует интерактивную зонированную карту проекта.

Пакет для маркетплейса Claude Code, закрывающий разрыв между уже отгруженным рендерером composed-map в forgeplan-web (фаза P0) и реальными данными проекта: до этого пакета сканера не существовало вовсе, и рендерер рисовал только рукописную тестовую заглушку. Этот пакет — генерирующая половина: полностью оркестрованный, детерминированно-гейтованный конвейер, а не короткий скрипт.

> [!WARNING]
> Требует `forgeplan` CLI v0.25+ (playbook-runtime + read-only MCP-поверхности `forgeplan_graph`/`list`/`get`). Сканирование — **только локальный headless-запуск**: сервер `forgeplan-web` структурно не может запустить `claude` (он шеллит только бинарник `forgeplan`, и только read-only подкоманды), поэтому кнопки «запустить анализ» в веб-интерфейсе нет и не будет. `/map-build` (или эквивалентный headless-вызов `claude -p`) запускаете сами, в целевом репозитории.

## Быстрый старт

```bash
/plugin install forgeplan-map-pack@ForgePlan-marketplace
/reload-plugins
```

Затем, в любом forgeplan-проекте:

```bash
claude -p '/map-build' --add-dir <репо> --allowedTools Read Glob Grep Write Task
```

Это сканирует репозиторий, классифицирует тип проекта, извлекает граф зон/узлов/рёбер и пишет `.forgeplan/map/map.json` со статусом `"proposed"`. Дальше детерминированный guardian-гейт либо переводит его в `"confirmed"`, либо чётко сообщает, что именно блокирует.

Результат — **карта понимания архитектуры** (v0.7.0), а не свалка артефактов: зоны это архитектурные регионы с RU-описаниями, узлы — реальные модули с богатыми RU-объяснениями из настоящего кода, переполненные зоны схлопываются в читаемые группы по типу (а не в одну непрозрачную карточку), а именованные чипы потоков подсвечивают сквозные пути.

Углубиться по требованию — **`/map-build-layer "<zone>"`**: генерирует под-карту одной зоны (`.forgeplan/map/layers/<zone>.json`), архитектурную карту того, что у зоны внутри.

Поддерживать в актуальном виде дёшево: **`/map-doctor`** — быстрая read-only диагностика (прогоняет детерминированный guardian по карте и всем слоям, помечает устаревшие слои и сироты, печатает команду-лечение для каждой проблемы), а **`/map-refresh`** перестраивает ТОЛЬКО те слои, чьё содержимое реально изменилось после сборки — определяет по git и докам (в отпечаток слоя вшита git-подпись содержимого его карточек, поэтому правку файла — а не только добавление/удаление карточки — он видит). Доктор находит, refresh чинит.

## Экспорт в LikeC4

`scripts/map-to-likec4.mjs` детерминированно переводит существующий `forgeplan.map/v1` в `.c4`: зоны становятся контейнерами, узлы — вложенными элементами, рёбра сохраняют направление и тип, потоки — отдельными dynamic views. Скрипт не сканирует проект заново, не меняет `map.json` и не создаёт ForgePlan-артефакты.

Оба скрипта запускаются обычным Node из Claude Code, OMP, Codex или терминала. `MAP_PACK` — фактический каталог установленного пакета в текущем runtime либо `plugins/forgeplan-map-pack` в checkout, не угаданная версия в чужом cache:

```bash
MAP_PACK=/absolute/path/to/forgeplan-map-pack
node "$MAP_PACK/scripts/map-to-likec4.mjs" .forgeplan/map/map.json --out project-map.c4
node "$MAP_PACK/scripts/verify-likec4.mjs" .forgeplan/map/map.json
```

Для конвертации достаточно Node; verifier дополнительно требует установленный `likec4` в `PATH` и ничего не устанавливает. Он вызывает настоящий `likec4 validate --json --no-layout`, затем `likec4 export json --skip-layout` в одноразовом проекте. Для сохранения его `model.c4`, `likec4.config.json` и `model.json` передайте отдельный существующий пустой каталог:

```bash
WORK_DIR="$(mktemp -d)"
node "$MAP_PACK/scripts/verify-likec4.mjs" .forgeplan/map/map.json --work-dir "$WORK_DIR"
likec4 serve "$WORK_DIR"
```

- При отсутствии `edge.namespace` применяется [канон edge-verifier](skills/edge-verifier/SKILL.md#algorithm-1--namespace-classification-spec-003-ss-d3-default-rule): 11 артефактных relations дают `typedLink`, остальные, включая `imports`, — `codeDep`. Явный namespace имеет приоритет.
- Для шага потока сначала выбираются связи нужного направления, затем допускается обратный обход. Непустой `edge_ids` ограничивает выбор указанными рёбрами; это набор всего пути, а не позиционный список по одному ребру на шаг. Отсутствующий или пустой набор допускает поиск среди всех рёбер. Обратный обход сохраняет исходное направление и ID model relationship, а видимую стрелку задаёт нативными `head none; tail normal` — обратная модельная связь не выдумывается.
- Неизвестные узлы, неразрешимые/неоднозначные `edge_ids`, отсутствующие/повторные ID потоков и цепочки короче двух узлов не пропускаются молча: converter завершается с `1` до записи, verifier — с `MISMATCH / 1`. Узел из середины цепочки не удаляется ради получения «рабочего» потока.
- Существующие реальные дети `collapsed` mega вкладываются в него: FQN ребёнка становится, например, `core.group.a`. Сырые ID остаются в таблице соответствия и `children` metadata, все исходные рёбра сохраняются. Отсутствующий ребёнок не превращается в фиктивный элемент. Это позволяет нативному шагу `group → b` ссылаться на настоящую связь `a → b` через иерархию.
- **Граница LikeC4 1.59.3:** dynamic step связывается со всеми отношениями нужного направления между участниками, включая их детей. `kind`/подпись шага не выбирают одно отношение; per-view `include` добавляет контекстные элементы, а не фильтрует отношения, и dynamic `exclude` не поддерживается. Поэтому непредставимый точный выбор подмножества параллельных связей даёт явную ошибку converter `1` до записи и verifier `MISMATCH / 1`. Все статические связи сохраняются; неподходящие связи/потоки не удаляются ради `MATCH`. Если выбраны все нативно связываемые отношения, такой шаг поддерживается. Это контракт проверенного runtime, не обещание возможностей будущих версий.
- ID с начальным дефисом или цифрой получают буквенный префикс; коллизии после нормализации разрешаются суффиксами. Сохраняются правила reserved words, подчёркиваний и экранирования строк.

Коды verifier: **`0` — `MATCH`** для совпадения зон/узлов, направления/реального kind/relation рёбер и упорядоченных шагов потоков. Для каждого шага проверяются видимое направление стрелки, kind, подпись и фактические нативные relationship IDs через словарь отношений экспорта. **`1` — `MISMATCH`**, включая непредставимый точный выбор связей; **`2` — `CANNOT RUN`**, например при ошибке JSON, отсутствии CLI или неразбираемом DSL. Отсутствующий или неизвестный kind в экспорте не подменяется `typedLink`. Полностью пустая карта возвращает `EMPTY / 0`, а не содержательный `MATCH`.

Это проверка точности перевода уже объявленного содержимого, не полноты исходного сканирования и не внешнего вида. Она не проверяет заголовки/описания views, подписи узлов/зон, читаемость и раскладку; просмотр в браузере остаётся отдельной проверкой. Поведенческие регрессии включают исходные fixtures независимого review и изменения только DSL перед настоящим парсером: неверная binding при прежних подписи/видимом направлении, потерянная связь свёрнутой группы, неверные kind/подпись и сокращённая цепочка.

## Что внутри

### 8 агентов (`agents/`)

Полный оркестрованный конвейер — детали в [ARCHITECTURE.md](ARCHITECTURE.md). Коротко:

| Агент | Стадия | Роль |
|---|---|---|
| `map-orchestrator` | дирижёр | Диспетчеризует все стадии, проверяет 4 гейта, сам ничего не пишет |
| `code-scanner` | SCAN | Дерево исходников, манифесты, точки входа → свой scratch-файл |
| `forgeplan-scanner` | SCAN | Граф артефактов `.forgeplan/`, read-only MCP → свой scratch-файл |
| `docs-scanner` | SCAN | README/доки → факты RU-нарратива, только реальная проза, никогда не выдумывается |
| `zone-extractor` | EXTRACT | Сливает 3 скана в зоны/узлы/мега-узлы, минтит content-hash id |
| `edge-verifier` | VERIFY | Классифицирует рёбра, grep-подтверждает кодовые зависимости, отбрасывает неподтверждённое |
| `map-emitter` | EMIT | Единственный автор содержимого `map.json`, атомарная запись, `status: "proposed"` |
| `map-guardian` | VALIDATE | Запускает детерминированный скрипт-гейт; только его `exit 0` — путь к `"confirmed"` |

### 3 скилла (`skills/`)

Переиспользуемое алгоритмическое знание за тремя самыми ответственными агентами — точная формула вывода id, правила биннинга зон и схлопывания мега-узлов, дисциплина классификации доверия рёбер и argv-safe grep. Вызываются одноимёнными агентами, это не general-purpose инструменты.

### 3 шаблона композиций (`compositions/`)

Данные, не код — как сканированный проект превращается в зоны. `rust-cli-mcp` и `web-fullstack` — вручную настроенные догфуд-цели; `generic` — пол корректности, который всегда рисует хоть что-то, даже на репозитории, который не узнали два других шаблона.

### Контракт (`schemas/map.schema.json`)

Структурная JSON-схема, которой обязан соответствовать любой `map.json` — общая точка отсчёта для эмиттера, guardian'а и собственного клиентского валидатора forgeplan-web.

### Гейт (`scripts/map-guardian.mjs`)

Детерминированный Node-скрипт без внешних зависимостей — никогда не LLM-вызов. Одиннадцать проверок (GC-1..GC-11) плюс две кросс-source-проверки (XC-1/XC-2), независимо пересчитанные из эмитированного документа и реального состояния репозитория. GC-7..GC-11 (v0.11.0) добавляют гейты полноты и канонизации контента — `found_at`, полнота потоков, канон layer-meta, kind мега-узлов, коллизии accent у соседей. Только его `exit 0` переводит карту в `"confirmed"`.

### Хук защиты записи (`hooks/`)

Fail-closed PreToolUse-гейт: ни один агент в этом пакете не может писать никуда внутри `.forgeplan/`, кроме `map/map.json` и `map/.work/**`, независимо от того, во что уболтали промпт агента. Это один из трёх независимых, слоёных контролей — см. раздел «EMITTER-safe» в ARCHITECTURE.md о том, почему одного денилиста недостаточно.

## Принципы дизайна

- **Оркестровано, не автономно в одном контексте.** Каждая стадия работает в своём изолированном контексте — та же дисциплина «генератор не проверяет сам себя», что используется в этом маркетплейсе для BMAD/SPARC/TDD.
- **Детерминировано по построению.** Content-hash id узлов, ни один узел никогда не несёт `x`/`y`, геометрией владеет чистая функция раскладки. Повторный прогон добавляет узлы, не перетасовывая уже существующие.
- **Карта производная, не авторская.** Она в .gitignore, как `lance/` — удали, перезапусти, получи то же самое (с поправкой на реальные изменения репозитория). Ни один forgeplan-артефакт этим пакетом никогда не мутируется; контроли пути записи делают это структурно, а не просто по договорённости.
- **Гейтовано честно.** Каждая гарантия этого пакета — либо реально работающая детерминированная проверка, либо явно помеченная как обеспеченная соглашением, а не структурой. Ничего не заявляется без реальной проверки за этим.
