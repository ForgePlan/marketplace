# Structurizr C4

Плагин строит архитектуру по исходникам и документам, создаёт согласованные C4-схемы и проверяет линии и подписи после сохранения и экспорта. Это **основной C4-вход** для проектов ForgePlan: `adr-architect` и `architecture` делегируют ему новые и изменяемые архитектуры; рецензенты и `guardian` сверяют результат с нативным контрактом поставки.

## Где хранить правила

Общий процесс и правила качества находятся в [SKILL.md](skills/structurizr-c4/SKILL.md).
Нативный контракт ForgePlan — отдельный [references/forgeplan.md](skills/structurizr-c4/references/forgeplan.md); именно по нему проверяется приёмка C4-строки. Детали маршрутов — в [line-routing.md](skills/structurizr-c4/references/line-routing.md), смысловая проверка — в [c4-review.md](skills/structurizr-c4/references/c4-review.md).

Агент — тонкая роль Profile C-coder, ограниченная только архитектурными файлами: модель, отчёт, JSON-раскладка и экспорт. Ему запрещено менять product source, инфраструктуру и `.forgeplan/`, а также создавать, связывать или активировать артефакты. Решения по границе и неизвестные архитектурные параметры эскалируются автору ADR/RFC. Команды — точки входа. Поэтому новые исправления вносятся в навык и его проверки, а агенты используют одну и ту же актуальную инструкцию.

В навык уже входят правила: выбирать масштаб схемы, проверять линии через посторонние блоки и подписи, доводить отдельные маршруты, сохранять JSON с геометрией, повторно открывать viewer и проверять готовый экспорт. Ноль находок приблизительного сканера дополняется визуальным просмотром — без него приёмка C4-строки в `guardian` остаётся CONCERNS.

## Как использовать

Для повторяемого исправления включены: чтение нативного SVG, маршрутизатор с обходом препятствий и безопасное применение раскладки с резервной копией. Инструкция — [routing-tools.md](skills/structurizr-c4/references/routing-tools.md). Скрипты сохраняют модель, IDs, порядок шагов и все связи; после расчёта агент обязан проверить реальный рендер. Проверка инструментов: `bash tests/test-routing.sh`.

- В Claude Code: `/structurizr-c4:c4-build` для новой/as-is/to-be модели; `/structurizr-c4:c4-review` для producer-side ремонта уже существующего workspace. `c4-review` **не заменяет** `architect-reviewer`, `system-dev` или `guardian` и не выдаёт verdict по собственной работе.
- В Codex: установить навык через механизм skills своего клиента и вызвать `$structurizr-c4`. Если runtime клиента не поддерживает Claude subagent, используется его собственный worker с тем же переносимым навыком и теми же ограничениями Profile C-coder. Interop-ссылка `.agents/skills/structurizr-c4` ведёт на тот же исходник.
- Для выделенного Codex-субагента подготовлен [TOML-шаблон](adapters/codex/structurizr-architect.toml). Его нужно подключать отдельно по правилам установленной версии Codex. Claude-манифест сам его не регистрирует.

Нужны официальный `structurizr`, Python 3.9+ и браузер для просмотра SVG. На macOS приложение устанавливается через Homebrew. Плагин не устанавливает программы и не запускает сервер при подключении. **Native-инструмент и браузер обязательны** для закрытия C4-строки; без них модель остаётся draft с явной пометкой о непроверке.

## Нужен ли MCP

Для этого процесса MCP не обязателен. Агент уже умеет читать и менять DSL/JSON, вызывать официальный инструмент, открывать viewer и проверять отрисованные схемы. MCP можно добавить как отдельный интерфейс к подтверждённым операциям, если конкретному клиенту это удобнее. Он не гарантирует качество маршрутов и не заменяет просмотр экспорта.

В пакет не включены автозапуск, регистрация MCP, загрузка в облако или фоновые задания. Это отдельные решения после проверки конкретного сервера и его возможностей.

У проверенного официального MCP транспорт HTTP `/mcp`, а не stdio. Он умеет работать с DSL и текстовыми экспортами, но не заменяет отрисовку схем и доводку маршрутов. Подробности и источники — в [справке MCP](skills/structurizr-c4/references/mcp.md).

## Что передавать вместе со схемами

`workspace.dsl` хранит модель. `workspace.json` хранит доведённую геометрию: координаты, вершины линий, положения подписей. После ручной доводки нужны оба файла. Финальный static/JSON-экспорт выполняется с `--use-layout`; Mermaid и PlantUML служат дополнительными исходниками для других рендеров и **не закрывают C4-строку** в `guardian` или `methodology-check`.

Полная поставка C4 включает: `workspace.dsl`, сохранённый `workspace.json`, `evidence.md`, `assumptions.md`, `review.md` и нативный static-экспорт в `exports/static/`, выполненный с `--use-layout`. Для ADR или RFC дополнительно пишется навигационный отчёт `docs/c4/<ARTIFACT-ID>.md` со ссылками на эти артефакты; копировать модель туда не нужно.

## Состояние интеграции

Плагин — основной C4-вход ForgePlan. Он публикуется в `plugins/structurizr-c4/`, подключается через `agents-pro`, `agents-sparc`, `forgeplan-brownfield-pack`, `fpl-skills`, маршрутизацию `smith` и operating contract v4 в `fpl-init`. Старый Mermaid-генератор `plugins/fpl-skills/skills/c4-diagram/` удалён в `fpl-skills 2.0.0`; старые Mermaid-документы остаются историческими источниками и не закрывают новую C4-строку.

Проверка совместимости без установки: `bash tests/test-marketplace-compat.sh [папка-маркетплейса]`. Без аргумента скрипт определяет каталог из собственного положения на диске, с одним аргументом — берёт явный путь, при двух и более — отказывается с usage и exit 2. Скрипт читает реальные проверки маркетплейса и запускает их на временной копии пакета. Исходный репозиторий и глобальные настройки остаются без изменений; проверяется только конкретный пакет.
