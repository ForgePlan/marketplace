# slopocop-code

**Полицейский против слопа в коде.** Находит следы машинной генерации в исходном коде и убирает
их *без изменения поведения*. Кодовый собрат [`slopocop`](../slopocop) (текст) и
[`slopocop-design`](../slopocop-design) (дизайн) — та же схема, другой участок.

## Что делает

- **Находит** признаки AI-слопа в коде — избыток комментариев, комментарии, повторяющие следующую
  строку, декоративные баннеры-разделители, эмодзи в исходнике, заглушки `TODO: implement`,
  глубокую вложенность, идентификаторы длиннее 30 символов, кашу из имён
  `data`/`result`/`temp`/`manager`/`handler`, абстракции с единственной реализацией и
  скопированные блоки — и ставит оценку человечности от 0 до 100.
- **Убирает слоп** — переписывает отпечаток машины, сохраняя поведение в точности: без изменения
  API, без изменения логики, без переименования публичных символов. Только косметика и структура.
- **Ревью** — агент `code-slop-cop` по запросу: запускает сканер и выдаёт ранжированный список находок.

**Языки:** JavaScript / TypeScript, Python, Go, Rust, Java, PHP.

## Компоненты

| Тип | Имя | Назначение |
|------|------|---------|
| Скилл | `code-slop` | База знаний: контракт из 10 метрик, пороги по языкам, список разрешённых идиом, плейбук de-slop |
| Команда | `/code-audit` | Только чтение. Запускает сканер, возвращает ранжированный отчёт + оценку 0–100. Без правок |
| Команда | `/code-deslop` | Переписывание без изменения поведения. Снимает отпечаток, код делает ровно то же, что и раньше |
| Агент | `code-slop-cop` | Ревьюер кода по запросу — сканер + находки, самые серьёзные сверху |
| Сканер | `scripts/scan_code.py` | Детерминированный счётчик 0–100, годится для CI, выходит с ненулёвым кодом ниже порога |

## Как пользоваться

Скиллы срабатывают на естественный язык — «этот код написан нейросетью?», «почисти этот слоп»,
«убери слоп из файла». Если не сработали — позовите по имени: «запусти code-slop на этом».

Явные команды:

- `/code-audit <файл-или-папка>` — отчёт с находками и оценкой, без правок.
- `/code-deslop <файл-или-папка>` — переписывание, которое снимает отпечаток, не меняя поведение.

## Сканер

Детектирующая половина детерминированная — `scripts/scan_code.py`. Он считает ровно десять метрик:

1. **comment_ratio** — строки-комментарии / строки-кода (на файл и на функцию). Высоко = слоп.
2. **redundant_comment** — комментарий, слова которого — подмножество следующей строки кода (пересказ кода).
3. **banner_comment** — декоративные комментарии-разделители (`// =====`, `# -----`, `/* ---- */`).
4. **emoji_in_source** — кодовые точки эмодзи вне строковых литералов.
5. **todo_placeholder** — `TODO: implement`, `your code here`, `stub`, пустые тела-заглушки.
6. **max_nesting_depth** — самая глубокая вложенность блоков на функцию.
7. **long_identifier** — идентификатор длиннее 30 символов.
8. **generic_name_density** — частота имён `data`/`result`/`temp`/`tmp`/`obj`/`item`/`helper`/`util`/`manager`/`handler`/`foo`/`bar`.
9. **single_impl_abstraction** — interface/abstract/trait ровно с одной реализацией или одним использованием.
10. **duplicate_block** — почти одинаковые участки ≥ 3 строк (копи-паст с одним изменённым значением).

Оценка начинается со 100; взвешенные вычитания дают полосу: **≥85 чисто** / **60–84 точечные правки** /
**<60 переписывать**. При оценке ниже 60 сканер выходит с ненулёвым кодом.

```
python3 <plugin>/skills/code-slop/scripts/scan_code.py file.py
python3 <plugin>/skills/code-slop/scripts/scan_code.py src/ --json
cat file.py | python3 <plugin>/skills/code-slop/scripts/scan_code.py -
```

Так как низкая оценка даёт ненулёвой код выхода, встройте сканер в pre-commit или CI — чтобы слоп не попадал в репо.

### Зависимости

Нет. Сканер — самодостаточный regex/эвристический анализатор на чистом Python 3, ставить нечего,
поэтому он сразу вешается на pre-commit или CI. `single_impl_abstraction` — эвристика с низким весом
(помечает объявление interface/abstract/trait без подсчёта реализаций между файлами); AST-путь мог бы
её усилить позже, но сегодня ничего дополнительного не требуется.

## Честно о ложных срабатываниях

Некоторые идиомы похожи на слоп, но корректны — и сканер настроен **никогда** их не помечать:

- **Go** — `if err != nil { return err }` и явный возврат ошибок.
- **Rust** — `Result`/`Option`/`match`/`?`, а также `unwrap()`/`expect()` внутри тестов.
- **Python** — обязательные docstring, когда их требует линтер.
- **TS/JS** — type guards на границах доверия.

Пороги свои для каждого языка. Если сканер и ваше суждение расходятся на идиоме — право за вами: оценка
это сигнал, а не приговор.

## Граница с code-reviewer и simplify

Разные инструменты, разные вопросы:

- **`code-reviewer`** — ищет баги. *Код корректен?*
- **`simplify`** — общее качество кода. *Код хорошо написан?*
- **`slopocop-code`** — отпечаток машины + детерминированная оценка для CI. *Это писал человек или
  модель?*

slopocop-code не ищет баги и не гонится за общим качеством. Он целится в AI-признаки и даёт одно число для
гейта. Запускайте его рядом с двумя другими, а не вместо них.
